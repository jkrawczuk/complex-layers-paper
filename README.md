# complex-layers-paper

Code, data artifacts, and manuscript files for the PeerJ Computer Science submission:

> Complex Layers of Sparse Formal Neurons for High-Dimensional Classification

This repository contains the implementation of Complex Layers classifiers, the exact scripts used for
the reported experiments, the input datasets, final manuscript figure assets, and the LaTeX manuscript source.

## Repository Contents

- `src/edu/but/` - Python package with Complex Layers models and experiment utilities.
- `scripts/` - reproducible command-line entry points.
- `data/` - datasets used by the experiments.
- `paper/` - PeerJ manuscript source and figure assets.

Generated experiment outputs are written under `results/`, which is intentionally ignored by git because raw
cross-validation prediction bundles can become large. The committed manuscript figures in `paper/figures/`
were generated from those local bundles.

## Requirements

- Python 3.13 or 3.14
- Poetry 2.x

Dependencies are pinned in `poetry.lock` and declared in `pyproject.toml`.

## Installation

```bash
poetry install
```

Run commands through Poetry:

```bash
poetry run python scripts/run_cv_predictions.py --help
```

## Quick Reproducibility Check

This small run verifies that the package imports, data loading, model fitting, and output writing work:

```bash
MPLBACKEND=Agg poetry run python scripts/run_cv_predictions.py \
  --data data/synthetic_signal.csv \
  --base-model svm \
  --C 2 \
  --n-neurons 2 \
  --cv-folds 2 \
  --cv-repeats 1 \
  --jobs 1 \
  --standardize-features \
  --verbose 0 \
  --out-dir results/smoke/three_step_svm
```

Then compute metrics and figures:

```bash
poetry run python scripts/compute_cv_metrics.py \
  --bundle-dir results/smoke/three_step_svm

MPLBACKEND=Agg poetry run python scripts/generate_cv_plots.py \
  --bundle-dir results/smoke/three_step_svm \
  --n-total-features 2000
```

Expected output includes raw prediction files, `metrics/*.csv`, and `figures/*.png`.

## Three-Step CV Pipeline

For new experiments, prefer the split pipeline. It separates expensive model fitting from cheap metric and
figure generation.

### 1) Fit models and save raw predictions

```bash
MPLBACKEND=Agg poetry run python scripts/run_cv_predictions.py \
  --data data/synthetic_signal.csv \
  --base-model svm \
  --C 2 \
  --n-neurons 2 \
  --cv-folds 2 \
  --cv-repeats 1 \
  --jobs 1 \
  --standardize-features \
  --verbose 0 \
  --out-dir results/smoke/three_step_svm
```

This writes:

- `raw_predictions.csv` - one row per split, train/test set, and sample, with `pred_n1`, `pred_n2`, ...
  columns for per-neuron predictions. Labels are encoded as `0`/`1`; bundle-level metadata are stored in
  `run_stats.json`.
- `class_labels.json` - mapping from encoded labels to original class labels.
- `neuron_summary.csv` - per-split, per-neuron feature counts, objective diagnostics, and synthetic recovery metrics.
- `selected_features.csv` - selected feature indices and coefficients per neuron.
- `run_stats.json` - run metadata.

### 2) Compute metrics from raw predictions

```bash
poetry run python scripts/compute_cv_metrics.py \
  --bundle-dir results/smoke/three_step_svm
```

This writes `metrics/results.csv`, `metrics/per_split_metrics.csv`, and weighted-vote summaries. The current
weighted-vote rule uses training-fold neuron quality only:

```text
q_i = max(0, train_neuron_balanced_accuracy_i - 0.5)
w_i = q_i / sum_l q_l
```

If all `q_i` are zero, the metric step falls back to uniform weights.

### 3) Generate figures from metrics

```bash
MPLBACKEND=Agg poetry run python scripts/generate_cv_plots.py \
  --bundle-dir results/smoke/three_step_svm \
  --n-total-features 2000
```

This writes figures under `figures/`.

## Reproducing the Paper Runs

The manuscript experiments can be regenerated by running the three-step CV pipeline for each configured
dataset/model/regularization bundle:

- `colon_cancer`: `cpl`, `svm`, and `logreg` at the selected regularization values.
- `synthetic_signal`: `cpl`, `svm`, and `logreg` at the selected regularization values.

Use 10-fold cross-validation repeated 10 times for the paper-scale runs. These runs are computationally
heavier than the smoke check and may take substantial time; in the current full run, high-feature `logreg`
and high-feature `cpl` were the longest-running configurations. The generated paper-run bundles are not
committed to git; the current local full-run output is under `results/paper_runs_v2/`.

## Data

- `data/synthetic_signal.csv` is the synthetic benchmark used in the manuscript.
- `data/synthetic_signal.metadata.json` records the synthetic-data generation parameters and ground-truth
  informative features.
- `scripts/generate_synthetic_signal.py` regenerates the synthetic benchmark CSV and metadata from the
  recorded design.
- `data/colon_cancer.csv` is the colon cancer microarray benchmark used in the manuscript. It is exported from
  the Alon et al. benchmark distributed by the Bioconductor `colonCA` experiment data package
  (DOI: `10.18129/B9.bioc.colonCA`; package license: LGPL).

For both datasets, paper runs pass `--standardize-features` so feature scaling is fitted on each training fold
and applied to the corresponding held-out fold.

Dataset provenance and licensing are tracked in `DATA_LICENSES.md`. The repository MIT license applies to the
source code only. The file `data/colon_cancer.csv` is redistributed as an export of the Bioconductor `colonCA`
dataset under the upstream LGPL package license, not under the repository MIT license.

## Output Bundle Format

Cross-validation runs write a directory containing:

- `metrics/results.csv` - aggregate metrics by neuron depth.
- `metrics/per_split_metrics.csv` - per-fold, per-depth metrics.
- `run_stats.json` - run configuration, timing, memory, and output paths.
- `accuracy.png`, `minority_metrics.png`, `precision_recall_trajectory.png` - predictive performance plots.
- `features_nth_neuron.png`, `available_features_per_neuron.png` - feature-use plots.
- `loss_l1_norm.png` - objective diagnostics.
- `feature_recovery.png` - synthetic benchmark feature-recovery plot when metadata is available.
