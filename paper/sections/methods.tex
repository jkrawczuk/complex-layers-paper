\section*{Materials \& Methods}

\subsection*{Dataset}
We use two datasets: one real benchmark and one synthetic benchmark.

\subsubsection*{Real-data benchmark: colon cancer}
We use the colon cancer dataset, originally introduced by \cite{alon1999}. It is a gene-expression
microarray benchmark built from colon tumor and normal tissue samples.
The tabular data used in this study are a CSV export of the expression matrix distributed by the Bioconductor
\texttt{colonCA} experiment data package, available through Bioconductor at
\url{https://bioconductor.org/packages/release/data/experiment/html/colonCA.html} and identified by DOI
\url{https://doi.org/10.18129/B9.bioc.colonCA}. The archived repository includes this CSV as the input table
used by the Python experiments.
In the commonly used machine-learning representation, the data matrix contains:
\begin{itemize}[noitemsep]
\item 62 objects (samples),
\item 2,000 gene-expression features,
\item binary labels: \texttt{tumor} (40) and \texttt{normal} (22).
\end{itemize}

The dataset originates from the Alon et al. colon adenocarcinoma study published in 1999 \cite{alon1999}
and has since become a long-standing reference problem for sparse learning and feature selection in
bioinformatics, with representative comparative results in \cite{guyon2002,dudoit2002,li2004}.

\subsubsection*{Synthetic benchmark with known informative features}
To assess feature recovery directly, we generate a synthetic binary classification dataset in which the
informative features are known by construction. The dataset contains a small set of signal-bearing variables
and many unrelated noise variables, so later neurons can be evaluated not only by predictive accuracy but also
by whether they recover additional informative features or move toward noise. It has:
\begin{itemize}[noitemsep]
\item 100 samples,
\item 2,000 features in total,
\item balanced classes: 50 negative and 50 positive samples,
\item 12 informative features,
\item 1,988 noise features.
\end{itemize}

The construction is based on three latent signal sources. For each sample $i$ and source
$b \in \{1,2,3\}$, a latent value $z_{ib}$ is drawn from a standard normal distribution. The three sources have
decreasing strengths $s=(1.2,\;0.9,\;0.6)$. The class score is generated directly from these latent signals:
\[
r_i=\sum_{b=1}^{3}s_b z_{ib}+\eta_i,
\]
where $\eta_i$ is Gaussian label noise with scale 0.55. The score is thresholded at its median, yielding
exactly 50 negative and 50 positive samples.

Each latent source is represented in the observed feature matrix by four informative features. For an
informative feature $j$ assigned to source $b$, the observed value is a noisy measurement of the corresponding
latent source:
\[
x_{ij}=w_j z_{ib}+\epsilon_{ij}.
\]
The feature noise $\epsilon_{ij}$ is Gaussian with scale 0.2. The weights $w_j$ decrease in absolute value
within each source and alternate in sign, so the informative variables are not all positively correlated with
the class label. The resulting matrix contains 12 informative features and 1,988 independent noise features.
Because the informative set is fixed by construction, the benchmark supports both predictive evaluation and
feature-recovery analysis.

\subsubsection*{Data preprocessing}
For the colon cancer benchmark, the input matrix was used as exported from the Bioconductor
\texttt{colonCA} package. No additional gene filtering or imputation was applied.

Both benchmarks were standardized within each cross-validation split. Feature means and standard deviations
were estimated on the training fold and then applied to the corresponding held-out fold. Class labels were
encoded internally by the classifier implementation for binary learning. Feature selection, neuron fitting,
voting-weight estimation, and all metric calculations were performed within the training/test split structure;
held-out test labels were not used during training or feature selection.

\subsection*{Model family}
The core model is a complex-layer classifier that sequentially trains sparse formal neurons and removes selected
features after each neuron. This construction follows the Complex Layers of Formal Neurons line of work
\cite{bobrowski2021,bobrowski2022}. For analysis, we treat neuron depth $n$ as a model dimension in its own
right. For each depth, we inspect both the prediction of the $n$-th neuron itself and the cumulative prediction
obtained by majority voting over the first $n$ neurons.

The label \texttt{cpl} refers to the convex piecewise-linear base learner used in this study. It is evaluated
inside the same complex-layer protocol as two standard sparse linear baselines: \texttt{svm}, a squared-hinge
linear SVM, and \texttt{logreg}, an L1-regularized logistic-regression learner.
The use of L1-type regularization is motivated by its long-standing role in sparse estimation and feature
selection for high-dimensional problems \cite{tibshirani1996lasso,ng2004l1l2}. For logistic regression, the
computational perspective is closely related to regularization-path methods such as \texttt{glmnet}
\cite{friedman2010glmnet}, while the practical large-scale linear classification setting is represented by
\texttt{LIBLINEAR} \cite{fan2008liblinear}.
These techniques were selected because they share the same sparse linear model class and therefore allow a
controlled comparison of neuron depth across three L1-regularized linear learners: LP-based hinge loss for
\texttt{cpl}, squared hinge loss for \texttt{svm}, and logistic loss for \texttt{logreg}.

For binary labels $y_i \in \{-1,+1\}$ and linear score $f(x_i)=w^\top x_i + b$, let $N$ be the number of
training samples in the current fold, $p$ the number of currently available features, and
$\lVert w\rVert_1=\sum_{j=1}^{p}|w_j|$. With larger $C$ corresponding to weaker effective regularization, the
fitted neurons minimize:
\[
\begin{aligned}
\texttt{cpl}:&\quad \min_{w,b}\ \lVert w\rVert_1
    + C\,\frac{1}{N}\sum_{i=1}^{N}\max\!\left(0,\,1-y_i f(x_i)\right),\\
\texttt{svm}:&\quad \min_{w,b}\ \lVert w\rVert_1
    + C\,\frac{1}{N}\sum_{i=1}^{N}\max\!\left(0,\,1-y_i f(x_i)\right)^2,\\
\texttt{logreg}:&\quad \min_{w,b}\ \lVert w\rVert_1
    + C\,\frac{1}{N}\sum_{i=1}^{N}\log\!\left(1+\exp(-y_i f(x_i))\right).
\end{aligned}
\]
For \texttt{cpl}, both the hinge-loss term and the L1 term are piecewise linear, so the sparse neuron can be
trained as a linear programming problem. In the diagnostic plots below, ``training loss'' denotes the empirical
loss term in these objectives, while ``L1 norm'' denotes $\lVert w\rVert_1$.

\subsection*{Regularization calibration}
Because the three base learners use different optimization schemes and induce sparsity at different rates,
their regularization parameters are not directly comparable on a shared numerical scale. To make the comparison
more interpretable, we calibrate two representative regularization settings for each model on each dataset.

The calibration procedure is intentionally simple. For a given dataset, model, and value of $C$, we fit only
the first neuron and record the number of selected features. We then choose two values of $C$:
\begin{itemize}[noitemsep]
\item a \textbf{low-feature} setting targeting approximately five selected features in the first neuron;
\item a \textbf{high-feature} setting targeting approximately twenty-five selected features in the first neuron.
\end{itemize}

This calibration does not make the models equivalent, and it is not intended to support a strict ranking of
the base learners. Its purpose is to place each learner in two interpretable feature-count regimes and then
study how that learner behaves as successive neurons are added. Realized first-neuron widths can still differ
across learners under cross-validation, especially when the sparsity path changes abruptly with $C$.
This choice follows the broader methodological view that comparisons between sparse learners should distinguish
the induced first-neuron width from the raw numerical value of the regularization parameter itself
\cite{ng2004l1l2,saeys2007review}.

\subsection*{Evaluation protocol}
For both benchmarks, we use repeated stratified cross-validation with a fixed random seed.
Both benchmarks reported in this manuscript use 10 folds and 10 repeats, giving 100 train/test splits for
each dataset and model configuration.
All preprocessing, feature selection, neuron fitting, and vote-weight estimation are performed within each
training fold before evaluation on the held-out fold.

Within each train/test split, the complex-layer procedure is applied as follows:
\begin{enumerate}[noitemsep]
\item The model is trained only on the training fold.
\item A sequence of up to 31 neurons is fitted.
\item After each neuron fit, features with non-zero coefficients are removed from the candidate pool
for subsequent neurons.
\item Predictions are computed on the held-out test fold.
\end{enumerate}

For each split and neuron depth $n$, we evaluate three predictive summaries:
\begin{itemize}[noitemsep]
\item \textbf{vote prediction}: majority vote over the first $n$ neurons;
\item \textbf{weighted vote prediction}: vote over the first $n$ neurons with weights estimated only from the
training fold;
\item \textbf{neuron prediction}: prediction of the $n$-th neuron only.
\end{itemize}
Ties in the unweighted vote are resolved by the prediction of the first neuron. Therefore, in the binary case,
the unweighted vote at $n=2$ is identical to the first-neuron prediction within any split where the second neuron
is available.

For the weighted vote, each neuron receives a non-negative quality score derived from its training-fold
balanced accuracy:
\[
q_j=\max\left(0,\mathrm{BA}^{\mathrm{train}}_j-0.5\right),
\qquad
w_j=\frac{q_j}{\sum_{\ell=1}^{n} q_\ell}.
\]
If all $q_j$ are zero, uniform weights are used. The chance-level offset of 0.5 makes neurons with no
above-chance balanced accuracy contribute zero weight. Because all weights are computed on the training fold,
this procedure does not use held-out labels.

For each depth $n$, metrics are then averaged over the splits in which that depth was actually available.
A depth can become unavailable in a split when the sequence stops early because no additional non-zero feature
set can be produced. We therefore report both the averaged metric values and the number of available CV splits
supporting each depth. Comparisons across depths should therefore be read together with the available-split
counts: a higher mean accuracy at a later depth can partly reflect the subset of splits in which that later
neuron could be built, rather than only the effect of adding another neuron. The main summaries are vote
accuracy, weighted-vote accuracy, $n$-th-neuron accuracy, selected features, training loss, and L1 norm.

For the synthetic benchmark, the known set of 12 informative features lets us separate predictive performance
from feature-recovery behavior. Feature precision is the fraction of selected features that are informative,
and feature recall is the fraction of all informative features that have been selected. Per-neuron summaries
show what each newly fitted neuron selects, whereas cumulative summaries show how much signal has been recovered
by the sequence up to depth $n$. This provides a direct check on whether later neurons add informative features
or mostly select noise.

\subsection*{Computational environment}
All experiments were implemented in Python and are distributed with the manuscript repository. The repository
specifies Python 3.13 or 3.14 with Poetry-managed dependencies; the final local verification used
Python 3.14.3 and Poetry 2.3.2. Package versions are pinned in \texttt{poetry.lock}, including
\texttt{numpy}, \texttt{scipy}, \texttt{scikit-learn}, \texttt{pandas}, and \texttt{matplotlib}. The paper-scale
runs were executed on a MacBook Air (Apple M2, 2022; 16 GB RAM) running macOS Tahoe 26.5.1. The repository
scripts provide the workflow for regenerating raw predictions, metric tables, and figures from the input
datasets.
